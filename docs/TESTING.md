# Testing and quality

## Automated checks

CI runs dependency installation, TypeScript checking, ESLint, Vitest, production build, then browser tests in Chromium and WebKit using an iPad-like landscape touch profile. Playwright tests should exercise visible input controls and user flows. A test-only `window.__game` surface may be used for deterministic setup/assertions only when `?test=1` is present; agree and document its contract with the gameplay implementation before relying on it.

The existing core gameplay suite runs in Chromium and WebKit at an iPad-like landscape viewport. Its thirteen flows cover optional help with no forced introduction; compact landscape/iPad control bounds, clutter and label limits; actual solid-obstacle collision; visible touch movement and locked transformations; actual star-button cage rescue, duplicate-rescue idempotence and fox save/reload; all 22 required cage jumps across the biomes; the city giant cow before the final gate opens; a nearby wildlife reaction; Flushington's reusable three-hit encounter; reset from Ocean to a clean Meadow save; all ten biome loads; the actual Meadow-to-Desert shortcut and a forward-gate chain through Winter, Savannah, and Desert; and the finale gate, five head stomps, five-heart feedback, persistence, continued exploration, and a thank-you replay while Flushington remains in the scene.

Three additional Playwright files add thirteen flows, all passed in both engines: eight regressions for hazard/world-edge recovery without lost rescues; Falcon flight and Shark swimming in Ocean and shallow Beach water; the other four mini-bosses' stomp/skip flow; saved sound, volume, and gentle-motion settings; pointer-cancel/blur release and orientation changes; portal discovery and map return; update deferral during a boss introduction followed by one saved activation; and Jazzy Finn's Ocean siren cue. Three cave flows traverse the bat rescue, saved crystal-nook discovery, and a surface exit, check relocation from a legacy save inside newly solid cave geometry, and recover a flyer landing beyond the cave floor before human exploration. Two resource checks exercise three world circuits and the procedural-fallback fox when the optional GLB fails. The clean local v0.3 run passed all 52 cases without retries. These checks establish the stated paths and bounded counts, not long-term hardware memory stability.

`window.__game` is available only on `?test=1` for snapshots and deterministic placement/travel/progression setup. Visible controls perform the tested player movement, jump, form selection, pause, reset confirmation, and cutscene skip. The all-22 run and boss tests use real descending collisions; the star button performs the first hit, while deterministic placements make subsequent collision assertions repeatable. Separate Chromium and WebKit iPad-emulation production-preview tests verify that the service worker controls repeat visits and serves both the app shell and bundled `/models/fox.glb` while offline.

Unit coverage checks every required creature against cage roof/bar bounds and includes exploration-route cases (all ten biomes without repeats, a direct return after a shortcut, no immediate forward return after full discovery, and distinct destinations), the 22-ID registry, duplicate rescue, transformation eligibility, boss gate and heart mapping, descending cage bounds, cave-graph connectivity and safe relocation, malformed/future save handling, migration, secret-ID filtering, and clamping. New audio unit cases cover gesture activation, mute/volume routing, original biome motifs/ambience, and the siren phrase; all 28 unit cases pass, including three resource-disposal cases. No suite exercises every individual creature ability, service-worker version replacement, sustained hardware performance, or physical-device interaction.

## Reporting

Keep an evidence link or note in the relevant issue or development log. Clearly distinguish automated browser coverage, desktop manual checks, and physical-device testing. An untested item stays Pending; partial work stays In progress. Report failed checks and known gaps alongside passes. Test output and screenshots under `test-results/` are local artifacts and are not committed.

CI gameplay sessions opt into `?test=1&software=1`, which renders the 3D canvas at half device scale to avoid software-GPU contention. CSS viewport, touch targets, real scene/models, movement, collisions, and save logic are unchanged. Local gameplay runs, visual captures, and production offline tests retain normal rendering.

CI Chromium explicitly selects its bundled SwiftShader backend. A local probe verified that backend through WebGL renderer metadata and completed a real cage rescue and transformation. This avoids depending on a hosted runner's virtual GPU.
