# Requirements and status

This matrix connects the brief to GitHub work, an accountable implementation owner, acceptance evidence, and automated coverage. **Verified** means the stated behavior passed the cited automation or live foundation check. **Implemented, partial verification** means code exists but some acceptance points lack direct tests. **Device check pending** means browser automation passed where available, while the stated physical iPad behavior remains unverified. **In progress** and **Planned** describe remaining work. A passing build alone does not verify player behavior.

Owners: **Root** coordinates runtime and integration; **Astra** owns 3D content, biome art, and assets; **Luna** owns quality automation, tracking, and deployment evidence. Shared ownership is shown where appropriate. Issue numbers link to the initial actionable backlog in the public repository.

## Proposed and optional content

The exact identities of two or three mini-bosses, some desert surprises, save storage format, and individual ability designs were left open by the brief. Keep those choices original and child-friendly; they remain **Proposed** until accepted into the game design. Optional map expansion, fast travel, snowmen/igloos, hidden passages, replayable finale gallery, adaptive graphics, and extra wildlife do not count as required rescues or block the final boss.

## Evidence notes

Automated gameplay runs use `?test=1` only for deterministic positioning/progression setup; visible controls still perform the player actions under test. Production offline verification uses a Vite preview build. The iPad landscape project is WebKit emulation, not a physical iPad. The playable v0.2 release and its live cross-version update were verified; see the development log. The final v0.3 runtime has its own main/Pages and public update evidence in the development log.

## October 19 player reports

The v0.3 automated baseline does not resolve every player-reported presentation/device problem. New reports are being handled as a focused follow-up: #27 boss orientation, #28 installed-iOS scrolling, #29 the City falcon sight line, #30 earlier/readable portal labels and a travel animation, and #31 more detailed, researched, distinct animal forms. The published v0.4 release implements those changes: all six bosses face the view; tall east-City façades clear the falcon approach; portal names appear at up to 25 units, stay readable above scenery, and travel has a disposable arrival ripple; all 22 animal models have distinct authored anatomy and movement; transformation/dialog scrollers have explicit native vertical gesture ownership. Local checks pass 75 unit cases and the focused boss/portal/scroll flows across Chromium/WebKit. Native renders were inspected at 1440×900, 1194×834 and 844×390. [Main/Pages run 39261567529](https://github.com/christopherrbrown3/transforminals/actions/runs/39261567529) passed all 75 unit, 58 browser and two offline cases with zero flaky/skipped cases. The exact public bundle and a saved public v0.3-to-v0.4 update/offline flow are verified.

Installed-iOS scrolling (#28) remains a physical-device confirmation: Chromium uses trusted touch swipes, while mobile WebKit uses scripted scrolling and real taps because its automation API has no drag gesture. No installed iPad PWA result or sustained hardware frame rate is claimed.
